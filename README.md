# byLYNCH

byLYNCH is a photographic, editorial and cultural archive, hosted on GitHub Pages with Jekyll.

**Public site:** https://bylynch.com/  
**Production branch:** `main`  
**Primary audience:** photography, Jamaican culture, art and music

## Content and architecture

- 52 published archive posts; original `/YYYY/MM/DD/slug/` permalinks are preserved.
- `_posts/`: articles and galleries in original WordPress-derived markup.
- `assets/uploads/`: original photographic assets. Preserve originals; optimize only through separate derivatives.
- `_data/featured.yml`: curated cover choices. Do not silently change these mappings.
- `_data/card_previews.yml`: curated and source-derived preview text used for index, archive and metadata; avoid automatic body-text teasers.
- `_data/content_flags.yml`: nine classified galleries; badges and **AdSense exclusions** depend on this.
- `_data/manual_ads.yml`: three publisher-issued manual ad slots. **Auto Ads and Auto optimise should remain OFF** in the AdSense dashboard.
- `_layouts/` and `_includes/`: shared page and advertising templates.
- `assets/css/site.css` and `assets/js/site.js`: card/gallery rendering and ad integration.

## Discovery and SEO

- `sitemap.xml` is generated by Jekyll from pages and public posts; `robots.txt` points crawlers to it.
- Shared metadata in `_layouts/default.html` includes canonical URLs, descriptions, Open Graph/Twitter metadata and schema.org JSON-LD.
- Homepage and archive covers use native image tags to support image discovery; original assets and crop treatments are preserved.
- Search indexing and Core Web Vitals must be verified in Google Search Console and a real browser, respectively.

## Checks and deployment

- `.github/workflows/quality-checks.yml` builds the Jekyll site and runs `scripts/check_site.py` on production changes and SEO staging branches.
- The automated checks cover sitemap, critical metadata, native cover markup, file integrity and classified-gallery advertising exclusions.
- GitHub Pages deployment is managed by GitHub. A passing CI build does **not** replace visual mobile/browser QA.
- Use a staging branch for significant changes, review the diff, test, then merge into `main`. Branch protection is an outstanding administrative setting.

## Editorial precautions

- Do not edit or censor the original artwork as part of SEO work.
- Never publish private/password-protected WordPress entries unless explicitly authorized.
- Archived comments retain correction/removal review procedures.
- Privacy and advertising-policy compliance remain separate from technical SEO readiness.
