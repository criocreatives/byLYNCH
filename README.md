# byLYNCH

byLYNCH is a photographic, editorial and cultural archive, hosted on GitHub Pages with Jekyll.

**Public site:** https://bylynch.com/  
**Production branch:** `main`  
**Primary audience:** photography, Jamaican culture, art and music

## Content and architecture

- 56 published archive posts (as of 27 October 2026); original `/YYYY/MM/DD/slug/` permalinks are preserved.
- `_posts/`: articles and galleries in original WordPress-derived markup.
- `assets/uploads/`: original photographic assets. Preserve originals; optimize only through separate derivatives.
- `_data/featured.yml`: curated cover choices. Do not silently change these mappings.
- `_data/card_previews.yml`: curated and source-derived preview text used for index, archive and metadata; avoid automatic body-text teasers.
- `_data/content_flags.yml`: nine classified galleries; badges and **AdSense exclusions** depend on this.
- `_data/manual_ads.yml`: three publisher-issued manual ad slots. **Auto Ads and Auto optimise should remain OFF** in the AdSense dashboard.
- `_layouts/` and `_includes/`: shared page and advertising templates.
- `assets/css/site.css` is the shared stylesheet; `assets/css/about.css` serves only `/about/`, and `assets/css/credits.css` serves only individual posts. Original CSS declarations and their order were retained in these extractions.
- `assets/js/site.js` manages navigation, masonry, infinite scroll and ad initialization. Search and photo lightbox live in `assets/js/search.js` and `assets/js/lightbox.js`; the lightbox loads only on individual posts.
- Search fetches the generated index with normal caching and a deployment-specific query version, so new site builds invalidate the cached index.
- The quality workflow syntax-checks all runtime scripts; `.github/workflows/visual-regression.yml` builds the exact pre-cleanup commit and staged revision, compares representative desktop/mobile screenshots and smoke tests key browser interactions. It uploads screenshot and lab-timing evidence.

## Discovery and SEO

- `sitemap.xml` is generated by Jekyll from pages and public posts; `robots.txt` points crawlers to it.
- Shared metadata in `_layouts/default.html` includes canonical URLs, descriptions, Open Graph/Twitter metadata and schema.org JSON-LD.
- Homepage and archive covers use native image tags to support image discovery; original assets and crop treatments are preserved.
- Search indexing and Core Web Vitals must be verified in Google Search Console and a real browser, respectively.

## Checks and deployment

- `.github/workflows/quality-checks.yml` builds the Jekyll site and runs `scripts/check_site.py` on production changes, fix/seo staging branches, and pull requests.
- The automated checks cover sitemap, critical metadata, native cover markup, file integrity and classified-gallery advertising exclusions.
- GitHub Pages deployment is managed by GitHub. A passing CI build does **not** replace visual mobile/browser QA.
- Use a staging branch for changes, review the diff, wait for CI, then update `main` only by a verified non-forced fast-forward. Do not rewrite production history.
- GitHub reports `main` is **not branch-protected** as of 27 October 2026. A repository administrator must configure a ruleset in GitHub Settings to require the quality check and block force pushes; the repository connector cannot administer branch rules.
- `scripts/check_site.py` validates generated HTML and curated metadata, but does not substitute for screenshot, browser-interaction, performance, or regional consent testing.

## Maintenance safety

- Original JPEG/PNG uploads under `assets/uploads/` are archival masters: never optimize them in place as part of publishing.
- The legacy in-place optimizer was removed from active code. The only supported derivative workflow is `scripts/build_responsive_covers.py`: incremental by default; `--only` and `--header-post` are explicit per-story operations.
- All post-gallery `img` elements now carry an explicit loading/decoding attribute, except intentionally eager-loading content; the post layout no longer injects duplicate HTML attributes.
- `scripts/annotate_gallery_dimensions.py` reads original photo dimensions (including EXIF orientation) and applies missing intrinsic metadata on a temporary staging branch. Never guess dimensions.
- There is no authenticated historic WordPress excerpt for Kråka or Swove in Ledish. Kråka intentionally has no archive blurb; Swove uses its original in-post caption instead of invented copy.
- The discontinued WordPress importer, in-place photo optimizer, migration manifest and migration-only workflow were retired on 27 October 2026. Their full source remains recoverable from Git history and the `backup/bylynch-pre-extended-cleanup-20261027` ref. The original 3 October WXR backup remains in the user's private file Library. Never publish password-protected posts or the migration export as a side effect of cleanup.
- The `_config.yml` exclude list keeps internal scripts, migration metadata and setup documents out of public Jekyll output while retaining them in Git.
- Curated `_data/card_previews.yml` entries drive archive card content; change those and the post excerpt together when the author approves editorial text.
- Both homepage and incremental loading intentionally insert an ad after six **photo** cards. Keep the three supplied manual ad slots and all nine content exclusions unchanged.

- `scripts/audit_external_links.py` and `.github/workflows/link-audit.yml` create review-only HTTP status reports. Rate limits, provider blocks, and timeouts are **inconclusive**, not permission to erase an original citation.
- Historic gallery alt text is preserved exactly. Many legacy photographs have empty or missing descriptions; meaningful replacements require photograph-by-photograph editorial review, not generated guesses.
- AdSense's nine exclusions and the three owner-issued manual slots are intentionally unchanged. Privacy & messaging and GA4 consent must be verified in their respective provider interfaces; GitHub build tests cannot certify legal compliance.
